# Capacity, Local

Question: can a program whose logical heap is 192 MiB to 2 GiB run exactly on an executor with 327,680 bytes of Wasm memory (four data frames and one control page), and does the result stay exact when the executor is interrupted and resumed in a fresh isolate?

## Inputs

- A deterministic 2 GiB backing file of 32,768 pages. Each page is AES-128-CTR output with a fixed key and a page-index IV. Pages are materialized on disk, not reserved.
- The guest is a dependent pointer walk in a hand-written Wasm module, lowered by Binaryen's Asyncify pass. The mutable variant writes each visited page to an overlay.
- The ordinary C guest is `guest.c`, compiled with clang and lowered by `src/compiler.ts`.

## Instrument

`scripts/probe/elastic/run.ts` builds the backing and the modules, then runs each case as a sequence of Node worker segments. Each segment resumes from the previous segment's Asyncify image. `compiled.ts` and `native.ts` run the C route and the native differential. `scripts/research/elastic-analyze.mjs` checks every row and writes `summary.json`. `scripts/research/elastic-verify-backing.mjs` reads the full backing back and checks every page against the generator.

## Artifacts

- `raw.json`: the 15-case local matrix, the full-scan record's inputs, and the segment records. Redacted: the directory field.
- `full-scan.json`: one case that fetches all 32,768 pages of the 2 GiB file.
- `compiled.json`: the C route at 192, 512 and 2,048 MiB. Redacted: the directory field.
- `native.json`: the unmodified native C module compared with the elastic result at 192 and 512 MiB.
- `backing-verification.json`: the byte check of the retained backing files. Its three rows are the raw, full-scan and read-only files. The read-only file is not promoted, so this record keeps its row as recorded.
- `summary.json`: generated by `elastic-analyze.mjs`.
- `source-final/`, `source-full-scan/`, `source-compiled/`, `source-native/`: the source epochs the recorded runs used. The analyzer checks the hashes of the first two and the compiled modules.

## Results

Exactness, from `summary.json`:

| Logical MiB | Executor Wasm bytes | Result |
| ----------: | ------------------: | ------ |
|         192 |             327,680 | exact  |
|         512 |             327,680 | exact  |
|       1,024 |             327,680 | exact  |
|       2,048 |             327,680 | exact  |

- The full scan fetches 32,768 pages (2,147,483,648 bytes) with 327,680 Wasm bytes, and returns the independently computed checksum.
- The mutable case verifies every changed page byte for byte against an independently computed page. The C route verifies its modified pages the same way.
- The native differential compares 738,197,504 bytes at 192 MiB and 512 MiB.
- Total backing bytes verified: 6,442,450,944, across the recorded files.

## Scope

- One machine, Node workers, and file-backed page versions. Process memory counters are not an isolate peak.
- Timings in `raw.json`, `full-scan.json` and `compiled.json` are single diagnostic observations. The local runs are not latency claims, and the wall-time fields are not compared.
- Aligned i32 reads and writes only. One trusted writer. No durable execution root.
- Controls are mechanisms. They are not reproductions of published systems. See [migration-controls](../migration-controls/README.md).
