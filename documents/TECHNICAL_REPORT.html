    Technical Report: Shared WebAssembly Memory and Ordered Speculation

    Folio runs native WebAssembly across several V8 isolates over one physical memory allocation. A compiler discovers regions of an ordinary Wasm program that can run apart, workers execute them against the shared bytes, and an ordered validator keeps the serial result. The original Wasm instance stays the coordinator: it keeps scalar results, control flow, mutable globals, tables and host effects.

    This document is the engineering reference. It records what the library does, which platform limits shape each backend, what every route costs, and which claims the evidence does not support. src/ holds the library, tests/ the gate, scripts/ the build, measurement and analysis tools, and experiments/ the deployed and local Cloudflare probes. results/ holds the raw samples, the exact source snapshots and the deterministic summaries behind every figure. Each figure names the instrument that produced it, because a Node wall clock, a deployed cpuTime reading and a platform tail event are not interchangeable.

    What Decides the Design

    Sharing is a host property. V8 can attach several wrappers to one backing store. Ordinary Worker RPC drops the backing-store table before delivery, MessageChannel refuses it, and managed Workers expose no way to create parallel agents over one allocation. Physical sharing therefore needs a host Folio controls: Node worker_threads, a self-hosted runtime, or a browser.

    The original stack is the continuation. Folio does not serialize Wasm frames. JSPI suspends the original Wasm stack while regions run elsewhere, so scalar carry, branches, nested calls and host effects keep their native semantics.

    Dependencies are validated, not assumed. Regions with a proved footprint run directly. Others run on private overlays over a frozen base and commit in original order, with replay on conflict.

    Copying is the managed cost. The managed route copies one frozen snapshot per lane batch and measured 1.618x end to end including setup, a serial oracle and close. No isolated kernel timing exists, so the data neither refutes nor supports fan-out for compute-heavy work on a small arena. It does show that copying whole arenas will not scale past the owner's memory.

    🎯 Scope and Acceptance

    The acceptance answer is "Arbitrary input; preserve serial dependencies." It means Folio accepts any valid program the host engine accepts, with its required host bindings, and keeps the serial result. It does not make an unknown dependency a proved serial one, and it does not promise that every program speeds up.

    The input domain is WebAssembly supported by the host engine. It is not arbitrary JavaScript, and it is not machine code without an adapter. A JS runtime compiled to Wasm can own its guest heap, and gmux can provide decoded blocks and explicit machine state. Required imports remain the program's host ABI. No claim covers joining independent JS or Wasm GC heaps through linear memory.

    Extraction has explicit admission rules (see Region Extraction). Nothing here claims that a finite test corpus proves every optimizer transformation correct, that every safe region is recognized, or that every accepted program is faster.

    🔬 Mechanism and Correctness

    Physical Sharing

    Each isolate gets its own wrapper around the same native backing store. It keeps its own instance, VM stack, globals, tables and JS heap. The allocation is neither duplicated nor moved away from its creator.

    On Node 26.10.0 the sender retains GetBackingStore() and the receiver builds another SAB wrapper from the same native handle [1][2]. V8 keeps the allocation alive while backing-store references remain [3]. The mutation, lifetime and copy-control probes test the observable consequences of that implementation.

    Region Extraction

    The fast path recognizes whole void countdown entries with affine i32 parameter updates. It accepts inline scalar temporaries when every read of a written local is dominated by a write in the same iteration, merges conditional definitions by intersection, and preserves Wasm operand order, including select and local.tee. It refuses reads of the changing remaining count, extra control-variable mutation, escaping or nested control, and scalar carry. A refusal records analysis coverage. It does not assert that no parallel algorithm exists.

    The generalized compiler (src/extract.ts) outlines contiguous inline scalar-memory statements with numeric live-ins. Modified locals must have no reads outside the span and must be definitely assigned before reads on every admitted path. Branch targets stay inside the region. These rules exclude scalar carry across repeated invocations, because capturing a stale local on each loop iteration would be wrong. The same path extracts discarded calls to transitive effect-free numeric functions, and tracks loads, stores and bulk operations inside a region.

    Region admission is static. prepare estimates each candidate in instruction units and keeps it at its owner below minimumRegionWork; see Static Admission and the Native Fallback. A module with no admitted region gets no control plan and runs as the original Wasm.

    The original Wasm engine remains the coordinator. It runs branches, nested loops and calls, switches, reductions and return values. Helpers evaluate operands in native order, then join pending regions before canonical memory, global state, growth, host effects or opaque calls. Opaque calls run with native execution forced, so synchronous reentry cannot spawn untracked work. Start and data initialization run once in this instance, and workers hold only the outlined or pure function closure plus the imported shared arena.

    JSPI suspends the original stack during joins [4]. Numeric-result controller exports get an internal promising wrapper; reference-returning exports keep their original ABI. Raw exports and serial paths select the original bodies through an imported mode global. The generated barrier and poll cross into JSPI only while an imported pending global is raised, which the coordinator does when a region is queued. Float region arguments are reinterpreted to i32 or i64 before crossing JS and worker messages, so operands keep their bits. A native coordinator trap drains earlier queued regions before it surfaces, and bounded polling prevents an earlier queued trap hiding behind later unbounded control flow.

    Ordered Speculation

    Queues hold at most 16 regions per participating worker, and one message carries one lane. Each worker runs its lane against the frozen base with a separate overlay per region. All lanes finish before the first commit. Commits and replays follow original region order.

    1. Workers read a frozen canonical allocation and keep private byte writes. Reads see their own earlier writes, and external reads are tracked.
    2. All speculative workers stop before any canonical commit.
    3. Regions validate in order. A preceding write that intersects a later read forces replay against the committed state. Blind writes commit in order, and byte granularity catches partial and unaligned overlaps.
    4. A validated trap commits that region's preceding writes, throws at the ordered head and discards later speculative results.
    5. Fuel or tracking exhaustion discards the overlay. If tracked replay also exhausts, the original native head and the rest of that batch run serially.

    The lane shares one retained tracking allowance across its results rather than multiplying it by 16, and exhausted later jobs return empty sentinels. A failed snapshot allocation or growth keeps native execution: an optimization resource refusal never becomes a Wasm trap. The same fallback covers explicit runAll batches whose shared-mirror refresh fails before dispatch.

    For deterministic admitted instructions, equal externally sourced reads imply the same region computation, so ordered writes and return values match serial execution. Fuel lets a region stuck on stale state yield to the native head. It does not make a nonterminating program terminate. The design follows established ordered speculative execution [5].

    A native guard additionally proves complete memory footprints, finite loops and nontrapping i32 arithmetic for the kernels it admits. Runtime checks reject bounds violations, pointer wrap and every cross-region read/write or write/write overlap before concurrent canonical writes. Guarded payload execution has no per-access translation, private overlay, byte log or commit copy.

    Resource Limits and Recursion

    The equivalence argument covers admitted deterministic instructions and their instruction-defined traps. Engine resource exhaustion is a separate boundary: native stack capacity, allocation failure and process termination vary with placement and instrumentation. Folio does not promise identical resource-limit thresholds in every isolate. A review found this through recursive calls, so direct and mutually recursive call components now keep their original bodies at the owner with ordered joins before entry. Whole-module legacy tracking refuses recursive call graphs. Tests cover native stack exhaustion and its exact preceding writes.

    Contract With the Host

    The host gives Folio exclusive access to the arena while a run is active. External writes or growth, concurrent raw-export calls, and callbacks that mutate tracked state outside this protocol break the contract. Prepared plans are trusted build artifacts, and Node JS imports are trusted host code. They are not a tenant sandbox.

    What Blocks Sharing on Managed Workers

    At workerd release v1.20261019.1 (commit 781048bc05cb205c92e503c1062ef3266ab959b5), JSG local cloning keeps a shared_ptr<v8::BackingStore>. Worker RPC keeps serialized bytes and drops the shared backing-store array, so the receiver has no matching handle. MessageChannel refuses shared backing stores outright, and the worker_threads shim does not create an execution agent [8][9][10][11]. The deployed failures agree with these source boundaries.

    Three independent blockers follow. RPC loses the backing-store table. MessagePort rejects SAB and only entangles ports inside one isolate. Managed Workers expose neither process-local placement nor a scheduler for parallel agents over one allocation. Enabling nodejs_compat changes available APIs and polyfills, and worker_threads, vm, cluster, child_process and v8 stay stubs. The Free and Paid plans show no difference in these semantics in anything measured here; the published limits (128 MB per isolate, no threads) are the same for both.

    A native workerd adapter needs a tenant-scoped arena registry, an unforgeable membership capability, same-process placement, retained backing-store lifetime, growth coordination, cancellation and explicit physical and private accounting. It must reject remote and cross-tenant attachments, and revocation stops new attachments while existing native references run down. Managed JS cannot install this registry through the tested RPC interface. That is a missing host capability, not evidence that V8 cannot share memory.

    🌉 Execution Host and Portable Client

    An edge Worker can keep its URL and stream a response from a Folio execution host. Sharing happens inside that host, and the request and result cross a network transport. This moves execution and does not merge Cloudflare isolate quotas.

    Changes.

    • prepare() estimates every candidate region in instruction units: nodes weighted by trip count, calls included, minus 3,600 units per tracked load or store. A loop bounded by a constant uses it, a loop bounded by an untouched parameter or a countdown from one becomes a term in that parameter, and any other loop uses assumedTripCount (1,000). A region below minimumRegionWork (200,000) is not a region. A parameter-bounded one is compared with the threshold at each call by a generated __folio_dispatch_N (a few f64 operations) and runs at the owner when it falls short. Both options are documented in AdmissionOptions; minimumRegionWork: 0 admits every pure region, which the unit tests use for their small fixtures.
    • The generated barrier and poll read an imported pending global and cross into JSPI only while it is
      1. The coordinator raises it when a region is queued and lowers it only after the queue is empty and the last flush has resolved and committed, so a stale value can only cost an empty crossing. Three mutations of that logic each fail a test (tests/unit/coordinator.test.ts, control-flow.test.ts).
    • When no region is admitted, or none has a call site, prepare() returns no control plan and Folio binds the original module with no Suspending imports and no coordinator. The decision is made once at prepare time; a unit test counts zero coordinator calls and checks the result against a raw instance.
    • Cost of the admission check on an admitted region: under 10 ns per call, against 2.5 to 3.9 us of dispatch. A lone admitted region still pays one JSPI round trip and a native run at the owner.

    Work and Span of a PHP Request

    Wave 4 (2026-10-20, Apple M2 Pro laptop, Node 26.8.2, not the rig) built a work-span profiler for php8.5.tuned.wasm. It answers a measurement question: given one recorded request and a stated set of removed dependence classes, how long is the longest chain of dependences that remains? Work and span are in Wasm IR nodes executed, so the trace does not depend on the machine. Time is not measured.

    Method. scripts/probe/worksp-instrument.ts rewrites the module with binaryen. It bumps f64 counters once per straight-line chunk and calls a hook for every load and store. A PHP userland call is a change of execute_data at the one call_indirect in execute_ex; an entry hook on execute_ex separates consecutive callbacks that reuse a frame address. A segment is the work of one frame between its child calls. scripts/analyze/worksp.ts keeps one 8-byte-granule shadow, builds the dependence edges (read, write and write-after-read by class) and evaluates finish[i] = weight[i] + max finish over kept predecessors. The ladder is M0 spawn and join only, M1 all conflicts, then M2 stack pointer renamed, M3 allocator renamed, M4 refcounts as deltas, M5 output ordered, M6 host calls buffered, M7 ordered speculation. Binding class is the class on the top span path whose edges carry the most weight; ties report every class. M7 drops write-after-read and write-after-write edges and turns a read-after-write edge into a replay when the writer finishes after the reader starts. Output schema folio.worksp.v2.

    Verification. A script with 100 function, 50 method, 25 static and 10 callback calls gives 186 invocations (main plus 185) in count mode and trace mode. A hand count of a loop gives 21n + 7 nodes and the instrumented module matches it. A first version lost nested loads and calls (loads undercounted by 23 percent on one input); tallies now equal the hook counts exactly and a test covers it.     Repairing the Positive Control

    Wave 5 (2026-10-20, same Mac) found why the wave 4 ladder read 1.000 on the eight sha256 chains. The 817,245 stack edges were not dead-stack reads. Four recorder defects and one modelling gap explain them. The chunk read set kept reads of words the same chunk had already written (about 130 M on the chain shape), and the store hook fired before its value operand, so a read inside the value looked written. Caller code that runs after a nested activation returns, such as array_map between two callbacks, was charged to the last callback, which linked sibling callbacks through the caller's C frame. Stack edges between unrelated invocations on the small shapes fell from 184, 17, 399, 12,064 and 104,520 to 0 with the three rules (upward-exposed reads only, dead stack below the chunk's starting stack pointer, activation exit ends its invocations). The dead-stack rule alone accounts for 0 to 7 edges, so that hypothesis is refuted as the main cause. The Drupal render, rerun with the rules, still reports 4 stack edges, so M2 to M7 stay invalid there.

    Task rung. WorkSpan.taskModel treats each outermost private invocation as one serial task on private state. Edges kept across a task boundary are spawn, stack read-after-write, and read-after-write of heap, output and host words (arguments, return value, effects). Everything else is private: allocator and runtime bookkeeping (the allocator extents plus gc_possible_root, gc_remove_from_buffer and zend_objects_store_put), static data, the interpreter's own state (the SP register, the activation frame, the opline word), write-after-read and write-after-write. Time is the larger of the longest dependence path with each task contracted and the owner thread's own work. The owner's nodes are one per opcode with program order dropped, so control dependences are not modeled and the figure is an upper bound with zero copy and merge cost. A site enters the private set only if the explicit task API reproduces the serial digest (scripts/probe/worksp-validate.ts).

    Distributed Page Ownership and Writeback

    src/pages.ts (@gmitch215/folio/pages) implements a bounded volatile directory, resident leases, immutable page-owner transport and a reference in-memory owner. Canonical state consists of page/version/owner references and explicit zero-page declarations, without a contiguous canonical heap. The wasm32 domain holds up to 65,536 pages of 64 KiB. Logical growth allocates metadata only.

    Acquisition locks all requested pages or none. Readers share locks; writers exclude other leases. Scopes contain tenant, session and directory incarnation; increasing fences identify immutable versions. Commit snapshots write views before its first await, stages every owner, rechecks expiry after each await and publishes the full manifest in one synchronous decision. Failure or lost response leaves the previous manifest intact. Idempotent discard fences delayed stage requests after cleanup. Expiry does not release a busy operation's locks. Transports must impose deadlines; a never-settling request keeps its locks and credits.

    Owner storage, leases, resident pages, commit snapshots, page lists and retired-version metadata have finite credits. Cleanup failures keep credits charged and eventually refuse further commits. Missing materialized versions raise errors; only declared zero pages become zeros. A stale or modified local view cannot mutate published owner versions. Escaped caller views cannot be physically revoked and lie outside admission accounting. Credits are not RSS measurements.

    Ten failure tests cover publication, conflicts, expiry across awaits, late staging, response loss, owner failure, cleanup bounds, growth, missing pages and stale scopes. The actual native Wasm probe (scripts/probe/pages-probe.ts, results/page-leases-20261020.json) compares an 8 MiB logical arena with an untouched native oracle: 6 MiB materialized over four owners with 2 MiB credit each, 512 KiB charged residence including commit snapshots, 256 KiB native region memory and 24 span executions. Every byte and the scalar result agree. Final leases, resident bytes and garbage are zero. This is local protocol evidence with copied pages and explicit spans, not deployed aggregate capacity or transparent native Wasm paging.

    The directory/ownership approach follows shared virtual memory [18]; fences follow generation sequencers [19]. One trusted directory may be active per scope. Restart requires a fresh incarnation, persisted manifest and transaction decision log, and durable or replicated owners. The reference implementation has neither crash recovery nor durable owners. Durable Objects can share globals and lose in-memory state on eviction [20]; names and retention cannot replace this recovery protocol.

    Arbitrary native Wasm needs a compiler address-rewriting boundary or an existing guest page ABI. Resolve and lease bounded spans before native execution, then write back before release/remap; no RPC occurs per native load. For unknown dynamic footprints, suspend at an instrumented fault or use a resumable interpreter with explicit logical-to-resident translation. That is the capacity path; allocating the whole native heap at the coordinator would restore the original quota. General browser CFG extraction without JSPI likewise needs a continuation/state-machine pass for locals, labels, calls, traps and ordered effects. Counted-loop dispatch does not provide that pass.

    PHP and Thunder. An earlier census found 1,183,236 scalar memory sites in the 13,401,751-byte PHP 8.5 artifact (active data ended at 4,206,482), plus 260 HEAP references and 21 invoke or JS-longjmp trampolines in the 400,452-byte glue. These are artifact-specific measurements, not a new census. A paged or shared integration must preserve initialization, stack and TLS, typed accesses, growth, libc bulk operations and every glue HEAP access. A wasm-SjLj build removes the JS longjmp trampolines, but synchronous vrzno Proxy callbacks still need an explicit value-based boundary before suspension [15][4]. An earlier re-entry interpreter loaded the real PHP module and returned PHP 8.5.2, extension API 20250925 and stack pointer 37916928, with 40,370,176 bytes of interpreter memory plus 64 MiB of contiguous guest memory. That proves binary compatibility and does not prove PHP boot or a Drupal render. For Thunder, an admitted backend is chosen before execution, URL, session, headers and cache metadata are kept, and a destructive out-of-memory is never recovered by replaying writes blindly. The local proof above covers an actual uncached render, SQLite, ROM and one caught exception. Deployed Thunder execution and broader callback and longjmp coverage remain separate consumer checks.

    gmux. Linux mappings, protection, fds and scheduling stay in gmux. Folio supplies execution, arena and validation primitives. Independent process execution is the natural first consumer; shared writable mappings and futex or atomic coherence need explicit semantics. Neither consumer takes a dependency on the other.
