    Class TaskTable

    A queue of named tasks in SQL with leases and attempt counts. Every method is one transition with no I/O, and the clock is an argument, so a caller controls time and a test can replay it.

    The table has no I/O, so it cannot flush: a caller that needs a transition to survive a reset awaits the storage's flush after it. Until then the transition can be lost, and no statement depends on the order of the others.

    Each statement reads and writes only the row it names and moves it along one way: queued to running, running back to queued or on to done or failed, never out of done or failed. A reset that keeps any subset of the statements of an event, in any order, leaves every row in a state that the next claim handles: a lost claim leaves the row queued, a lost complete or fail leaves it running until its lease ends, and a lost lease renewal shortens a lease that the next renew or a replay corrects.

    One rule changes when claim gets policies: a running row whose lease ended is claimed again only if its kind is resend. The claim statement itself carries that test, so it holds even when the statement that ends report rows was lost, and a report row is never claimed twice.
