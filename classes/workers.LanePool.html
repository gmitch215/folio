    Class LanePool

    The coordinator side of a durable lane pool. Tasks are rows in the object's own SQLite, lanes on other objects claim them by RPC, and a lane that resets loses only the tasks it was running: their leases end and the next claim replays them. A coordinator that resets loses only the transitions since its last flush; build a new pool over the same storage and call run or resume.

    A write is durable once an await or a flush has passed it, so the pool flushes after the three transitions that must survive (enqueue, claim, complete) and before anything depends on them. A failure report, a lease renewal and the expiry of a lease are not flushed: losing one only brings the same replay that a lane reset brings.

    Each id's result is written once. A task body runs at least once, so the result is exactly once in the table and effectively once for a task whose body is deterministic or idempotent.
